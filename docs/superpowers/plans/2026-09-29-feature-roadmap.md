# Алхимия: новые возможности после полировки

**Цель:** сделать игру удобнее и глубже, не меняя состав каталога и рецептов: отметить конечные элементы, раскрыть связи элементов, добавить подсказки, достижения, настройки громкости и анимаций, перенос прогресса, английский язык и в самом конце — темы.

**Ограничения:**
- Каталог (180 элементов, 176 рецептов), правило перекрытия и редкость по глубине не менять.
- Прежнее решение «только стиль, без новых механик из референсов» пользователь снял 2026-09-29 для пунктов этого плана. Уровни, опыт, очки, серии дней, ежедневные квесты, облако и аккаунт по-прежнему не делаем.
- Новые зависимости не добавлять: JSON — `org.json`, выбор файла — `ActivityResultContracts` из `activity-compose`, язык — `LocaleManager`.
- Каждый этап — своя ветка `feat/<этап>` от `master`, один или несколько коммитов, без push. Слияние в `master` после проверки и согласия пользователя. Релизов и тегов не делать, в `CHANGELOG.md` вести раздел «Не выпущено».
- Проверка каждого этапа: `./gradlew qualityCheck testDebugUnitTest assembleDebug`, целевые инструментальные тесты, эмулятор `claude-alchemy-qa` (`ANDROID_SERIAL=emulator-5580`), `font_scale 1.3`. Звук и вибрацию пользователь проверяет на телефоне.

## Этап 1. Основа данных
Файлы: `ProgressStore.kt`, `AlchemyViewModel.kt`, `ProgressRulesTest.kt`.
- [ ] Порядок открытия: `discoveryOrder: List<String>` в `PlayerProgress`, хранится строкой через запятую. Миграция: у старого сохранения порядок берётся из порядка каталога.
- [ ] Новые поля настроек: `musicVolume`, `effectsVolume` (0..1, по умолчанию 1), `reducedMotion` (null — следовать системе), `theme` (пока всегда `AETHER`), `onboardingSeen`, `activeHint`.
- [ ] Сериализация `PlayerProgress` ↔ JSON с полем `version` в отдельной чистой функции: на ней потом стоит экспорт. Неизвестные id элементов и рецептов при чтении отбрасываются.
- [ ] Unit-тесты: миграция старого сохранения, JSON туда и обратно, отбрасывание мусора.

## Этап 2. Что можно узнать об элементе
Файлы: `AlchemyCatalog.kt` (или новый `ElementLinks.kt`), `ElementDetailsDialog.kt`, `ElementsScreen.kt`, `ElementTile.kt`.
- [ ] Предрасчёт по каталогу: `recipesByResult`, `recipesByIngredient`, `finalElementIds` (сейчас 77 элементов не входят ни в один рецепт).
- [ ] Метка «Конечный» у открытых конечных элементов: в каталоге (пилюля `pill_badge_green` или значок), в карточке и в окне «Новый элемент». У неоткрытых меток нет.
- [ ] Карточка элемента: блок «Получен из» (известный рецепт иконками) и «Участвует в» (известные рецепты с этим элементом) плюс строка «Ещё N неизвестных сочетаний», у конечного — «Больше ни с чем не сочетается».
- [ ] Нажатие на элемент в блоках карточки открывает карточку этого элемента.
- [ ] Unit-тесты на предрасчёт (конечных ровно 77, у каждого не базового ровно один рецепт-источник).

## Этап 3. Рецепты и палитра
Файлы: `RecipesScreen.kt`, `HomeScreen.kt`, `AlchemyApp.kt`, `AlchemyViewModel.kt`.
- [ ] Нажатие на строку рецепта кладёт оба ингредиента на плиту (`SpawnAutomatically` дважды) и переключает на вкладку «Дом». Места мало — поведение как у обычного тапа по палитре.
- [ ] Фильтры рецептов: чипы групп (по группе результата) и сортировка «Недавние / По алфавиту» (`recent_clock`).
- [ ] Палитра «Открытые элементы»: выбор сортировки «Недавние / По алфавиту / По группам» через `dropdown_field`. Выбор запоминается.
- [ ] Инструментальные тесты: рецепт → два элемента на плите, фильтр по группе, сортировка палитры.

## Этап 4. Подсказки
Файлы: новый `game/Hints.kt`, `RecipesScreen.kt`, `HomeScreen.kt`, `AlchemyViewModel.kt`.
- [ ] Правило: подсказка выбирает рецепт, у которого оба ингредиента открыты, а результат нет. Сначала рецепты малой глубины. Если таких нет — подсказки нет (так не бывает до полного прохождения, проверить тестом).
- [ ] Две ступени: 1-е нажатие — силуэт результата и один ингредиент, 2-е — второй ингредиент. Активная подсказка сохраняется (`activeHint`) и не перебрасывается до открытия результата.
- [ ] Без лимитов, валюты и таймеров.
- [ ] Кнопка с `hint_bulb` на экране рецептов; ингредиенты подсказки можно положить на плиту так же, как рецепт.
- [ ] Unit-тесты правила выбора, инструментальный тест: подсказка → смешать → подсказка сменилась.

## Этап 5. Достижения и финал
Файлы: `Achievements.kt`, `AchievementsScreen.kt`, новый `ui/home/CompletionDialog.kt`.
- [ ] Новые достижения: 50, 100 и все открываемые элементы; первый эпический и первый легендарный; все конечные элементы. Все считаются из прогресса, без новых счётчиков. Названия согласовать с пользователем при реализации.
- [ ] Старые id не менять, чтобы уже полученные остались полученными.
- [ ] Экран завершения при 180/180: золотая панель, `discovery_burst_gold`, счётчики попыток и сочетаний. Показывается один раз, потом доступен из достижений.
- [ ] Unit-тесты: новые достижения считаются по прогрессу, базовые элементы не засчитываются.

## Этап 6. Настройки
Файлы: `SettingsScreen.kt`, `GameAudio.kt`, `AlchemyControls.kt`, `WorkspaceCanvas.kt`, `AlchemyApp.kt`.
- [ ] Громкость музыки и эффектов: `AlchemySlider` на арте `slider.png` рядом с переключателями. Громкость применяется сразу, переключатель остаётся как «выкл».
- [ ] «Меньше анимаций»: по умолчанию как в системе (масштаб анимаций 0). Выключает частицы, искры, покачивание и вспышки; перемещения и появление остаются без украшений.
- [ ] Перенос прогресса: «Сохранить в файл» (`CreateDocument`, `alchemy-progress.json`) и «Загрузить из файла» (`OpenDocument`) с подтверждением замены. Решает потерю прогресса при переходе debug ↔ release.
- [ ] Инструментальные тесты: ползунок меняет состояние, импорт повреждённого файла ничего не ломает. Выбор файла — вручную на эмуляторе.
